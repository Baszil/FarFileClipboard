# FarFileClipboard

**FarFileClipboard** — плагин для Far Manager 3 под x86, x64 и ARM64 от **Qwaduda**, связывающий обычную файловую панель Far с системным файловым буфером Windows.

[English](README.md)

## Команды

| Клавиши по умолчанию | Команда | Поведение |
|---|---|---|
| `Ctrl+Shift+C` | Копировать | Кладёт в файловый буфер Windows всё, что выделено `Insert`. Если выделения нет — ровно объект под курсором. |
| `Ctrl+Shift+X` | Вырезать | То же правило выбора, но буфер помечается как операция перемещения/вырезания. |
| `Ctrl+Shift+V` | Вставить | Вставляет **строго в каталог, который сейчас открыт на активной панели**. Объект под курсором никак не влияет на место назначения. |
| `Ctrl+Shift+D` | Вставить в каталог под курсором | Отдельная команда. Срабатывает только если под курсором реальный каталог; файл, `.` и `..` не принимаются. |
| `Ctrl+Shift+Z` | Отменить | Отменяет последнюю безопасно обратимую файловую операцию, выполненную самим FarFileClipboard. |
| `Ctrl+Shift+E` | Повторить | Повторяет операцию, которая только что была отменена через FarFileClipboard. |

В меню плагинов Far (`F11`) отображается один пункт `FarFileClipboard`. Он открывает собственное меню плагина; отмена/повтор там неактивны, когда соответствующего действия нет. Все шесть горячих клавиш настраиваются на одном экране в `Параметры -> Настройка плагинов -> FarFileClipboard`: `Ctrl+Shift+` фиксирован, меняется только латинская буква A-Z.

## Совместимость с файловым буфером Windows

В направлении Far -> Windows плагин кладёт обычные файловые пути в `CF_HDROP` и использует `CFSTR_PREFERREDDROPEFFECT`, чтобы различать копирование и вырезание/перемещение. Поэтому `Ctrl+Shift+C` / `Ctrl+Shift+X` из Far можно вставлять обычным `Ctrl+V` в Проводнике и других программах, понимающих файловый буфер Windows.

В направлении Windows -> Far сначала используется обычный `CF_HDROP`. Если же Проводник положил в буфер виртуальные Shell-объекты без реальных путей — например файлы, скопированные прямо из открытого ZIP-архива — FarFileClipboard получает `IDataObject` / `IShellItemArray` и передаёт их системному `IFileOperation`. Поэтому такие объекты можно извлечь непосредственно `Ctrl+Shift+V` или `Ctrl+Shift+D`, не распаковывая архив вручную заранее.

То есть поддерживаются оба направления:

- Проводник -> Far: копирование/вырезание обычных файлов и каталогов, а также копирование виртуальных объектов из ZIP Проводника; затем `Ctrl+Shift+V` или `Ctrl+Shift+D` в Far.
- Far -> Проводник: `Ctrl+Shift+C` / `Ctrl+Shift+X` в Far, затем обычный `Ctrl+V` в Проводнике.

Для вставки из виртуального Shell-источника безопасная история Undo/Redo не создаётся: у такого объекта может не быть стабильного исходного файлового пути. Новая такая вставка очищает предыдущую одноуровневую историю плагина.

## Отмена / повтор

История одноуровневая и относится **только к файловым операциям, выполненным самим FarFileClipboard при вставке**. Копирование или вырезание в буфер само по себе файловую систему не меняет и в историю не попадает. Операцию, выполненную уже Проводником после копирования/вырезания из Far, плагин отменить не может.

Для безопасности отмена записывается только тогда, когда целевые имена до вставки не существовали. Если Windows пришлось сливать каталог или заменять существующий объект, такая операция выполняется, но в историю отмены не попадает.

При отмене копирования созданные объекты удаляются через системный механизм Windows с `FOF_ALLOWUNDO` (Windows старается сохранить возможность восстановления). При отмене перемещения объекты возвращаются на исходные пути. Перед отменой/повтором плагин проверяет идентичность файловых объектов и отсутствие конфликтующих имён, чтобы не удалить или не затереть уже другой объект.

Любая новая успешная операция вставки заменяет предыдущую одноуровневую историю. Повтор доступен только после отмены.

## Языки и встроенная справка

В дистрибутив входят штатные для Far языковые файлы и файлы помощи:

- `FarFileClipboardEng.lng`
- `FarFileClipboardRus.lng`
- `FarFileClipboardEng.hlf`
- `FarFileClipboardRus.hlf`

Far автоматически выбирает нужный язык. Из настройки плагина можно открыть встроенную справку клавишей `F1`.

## Требования

- Far Manager 3 той же архитектуры, что и DLL плагина: x86, x64 или ARM64
- Windows
- Для сборки исходников: Visual Studio 2022 с C++ и CMake

## Сборка

Запустить:

```cmd
build.cmd x86
build.cmd x64
build.cmd ARM64
```

Готовые папки плагина появятся в `dist\FarFileClipboard-x86`, `dist\FarFileClipboard-x64` и `dist\FarFileClipboard-ARM64`.

x86 проверяется в настоящем 32-битном Far через GitHub Actions: workflow проверяет недекорированные экспорты Far API, обнаруживает плагин через F11 и выполняет автоматический Copy/Paste между двумя каталогами панели.

ARM64 дополнительно проверяется в GitHub Actions на нативном Windows ARM64 runner: запускается ARM64 Far с плагином, плагин обнаруживается через F11, после чего автоматический функциональный тест выполняет Copy/Paste между двумя каталогами панели.

Собрать все три варианта подряд:

```cmd
build-all.cmd
```

Создать отдельный ZIP для одной архитектуры:

```cmd
package.cmd x86
package.cmd x64
package.cmd ARM64
```

Создать все три архитектурных release ZIP и один универсальный ZIP со всеми тремя сборками:

```cmd
package-all.cmd
```

Универсальный `FarFileClipboard-1.0.2-all.zip` содержит `FarFileClipboard-x86`, `FarFileClipboard-x64` и `FarFileClipboard-ARM64`. Установщик читает PE-архитектуру именно целевого `Far.exe` и сам выбирает нужную папку; архитектура PowerShell или самой Windows на выбор не влияет.

## Установка

Скопировать всю папку `FarFileClipboard` в:

```text
<Far>\Plugins\FarFileClipboard\
```

или выполнить:

```cmd
install.cmd "C:\Путь\к\Far Manager"
```

Если `install.cmd` запущен прямо из Far, путь можно не указывать: установщик сначала определяет запущенный родительский процесс Far, затем проверяет `%FARHOME%`, затем стандартные установки в `Program Files` / `Program Files (x86)`. При установке в защищённый каталог Windows установщик сам запрашивает повышение прав через UAC. Если существующая `FarFileClipboard.dll` загружена запущенным Far, открывается отдельное окно установки: закройте соответствующий Far, после чего установка продолжится автоматически.

Архитектурный release ZIP содержит `install.cmd` и его рабочий `install.ps1` рядом с папкой `FarFileClipboard`. Универсальный ZIP содержит рядом три папки `FarFileClipboard-x86/x64/ARM64`. В обоих случаях после распаковки достаточно запустить `install.cmd`; перед копированием он печатает найденный `Far.exe`, его архитектуру, выбранную сборку и каталог назначения и отказывается ставить DLL чужой архитектуры.

Если раньше стоял прототип **FarPaste** или **CopyPaste**, его старую папку надо удалить перед запуском Far. FarFileClipboard намеренно сохраняет прежний GUID плагина. Старые настройки подхватываются, если они уже соответствуют модели `Ctrl+Shift+буква`; остальные старые комбинации заменяются значениями по умолчанию.

## Настройка горячих клавиш

Откройте **Параметры -> Настройка плагинов -> FarFileClipboard**. Все шесть команд находятся на одном экране.

Префикс `Ctrl+Shift+` фиксирован, а в каждом поле вводится только одна латинская буква `A-Z`. Строчная буква автоматически становится прописной. Кнопка **По умолчанию** возвращает `C / X / V / D / Z / E`. Одинаковые буквы для разных команд не допускаются.

Внутри настроек Far значение хранится в его служебном формате (`CtrlShiftV`), но пользователю плагин везде показывает привычную запись `Ctrl+Shift+V`.

## Поведение файловых операций

На том же экране настроек есть два независимых блока.

**Прогресс и отзывчивость:**

- Сама файловая операция выполняется в рабочем потоке; по умолчанию ввод при этом принадлежит модальному диалогу прогресса Far до завершения или отмены операции.
- По умолчанию FarFileClipboard показывает компактный модальный диалог в стиле штатного прогресса Far. Заголовок — просто **Копирование** / **Перемещение**, без имени плагина. Секции текущего файла и общего прогресса подписаны локализованными строками; для нескольких файлов или каталога показываются оба индикатора. Диалог забирает себе Enter/Esc/F10 и мышь, поэтому нажатия не проваливаются в панели Far. Кнопка **Отмена**, Esc и F10 открывают предупреждение в стиле Far с подтверждением Да/Нет: Нет продолжает ту же операцию, Да прерывает уже идущее копирование через отменяемый Win32-механизм.
- Запросы перерисовки прогресса объединяются и ограничиваются по частоте, поэтому тяжёлое копирование каталога не забивает обработку клавиатуры и мыши Far.
- Флажок **Использовать системное окно прогресса Windows вместо Far** по умолчанию выключен. Включать его стоит только если нужен именно проводниковый интерфейс Windows.

**Проверка операций:**

- Флажок **Предварительно проверять недопустимые операции** включён по умолчанию. Плагин заранее отсекает очевидно невозможные случаи, например попытку поместить каталог внутрь него самого или его потомка.
- Если флажок выключить, FarFileClipboard сразу передаёт запрос Windows. Это не отключает ограничения Windows: окончательное решение всё равно остаётся за системным файловым механизмом.

**Конфликты имён:**

- **Спрашивать, что делать** — значение по умолчанию. При совпадении имени появляется собственный Far-диалог: **Заменить / Пропустить / Переименовать / Отмена**. Для «Заменить» и «Пропустить» можно включить **Применить этот выбор ко всем оставшимся конфликтам**. При выборе «Переименовать» плагин спрашивает новое имя входящего файла или каталога.
- **Использовать поведение Windows** — конфликт полностью передаётся системному механизму Windows.
- **Автоматически переименовывать** — FarFileClipboard сам подбирает свободное имя по настраиваемому шаблону. По умолчанию: `{name} ({n}){ext}`, то есть `report.xlsx` -> `report (1).xlsx`, `report (2).xlsx`, а каталог `Photos` -> `Photos (1)`.

Шаблон редактируется прямо под режимами конфликтов. Доступны подстановки `{name}` (имя без последнего расширения; для каталога — полное имя), `{ext}` (последнее расширение вместе с точкой; для каталога пусто) и обязательный счётчик `{n}`. Кнопка **По умолчанию** возвращает шаблон `{name} ({n}){ext}`.

Для собственного режима конфликтов FarFileClipboard использует стандартные файловые операции Windows; плагин управляет выбором действия и, при автопереименовании, точным свободным именем до запуска операции. Замена/слияние существующего объекта намеренно не записывается в безопасную историю отмены, а вставка под новым свободным именем может быть отменена как обычная операция.

## Ограничения

FarFileClipboard работает с обычными файловыми панелями Far. Виртуальные панели архиваторов, FTP и других панельных плагинов намеренно не считаются источниками или каталогами назначения файловой системы. Это не мешает вставлять в обычную панель виртуальные Shell-объекты, скопированные, например, из ZIP, открытого в Проводнике Windows.

Файловые операции выполняются через системный механизм Windows. История отмены/повтора существует только внутри текущего экземпляра Far и не переживает его перезапуск.
